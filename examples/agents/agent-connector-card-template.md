# Шаблон карточки коннектора для AI-агента

Этот шаблон описывает коннектор, который используется агентом для чтения, записи или привилегированного доступа. Он не заменяет базовые требования к IAM, сервисным учётным записям, DLP, аудиту и управлению секретами.

Не указывайте реальные секреты, токены, адреса промышленных сред, имена пользователей или персональные данные.

<a id="1-identifikazia-konnektora"></a>

## 1. Идентификация коннектора

| Поле | Обязательно | Пример значения | Подтверждение |
| --- | --- | --- | --- |
| Идентификатор коннектора | Да | `connector-placeholder-001` | Карточка реестра или реестр коннекторов |
| Назначение | Да | `Чтение тикетов проекта EXAMPLE` | Процесс подачи или карточка реестра |
| Владелец | Да | `connector-owner-role-placeholder` | запись, связанная с RACI |
| Агент | Да | `agent-placeholder-001` | Карточка реестра |
| Идентификатор рабочего процесса | Да | `workflow-placeholder-001` | Процесс подачи или запись рабочего процесса |
| Тип доступа | Да | только чтение, запись, привилегированный доступ | политика действий агента и согласование коннектора |

<a id="2-ucetnaa-zapis_-i-oblast_-dostupa"></a>

## 2. Учётная запись и область доступа

| Поле | Значение |
| --- | --- |
| Используемая сервисная учётная запись | `svc-connector-placeholder` |
| Область доступа | `project:EXAMPLE`, `dataset:placeholder`, `queue:placeholder` |
| Разрешённые классы данных | публичные данные, внутренние данные |
| Запрещённые классы данных | данные ограниченного доступа, если нет отдельного согласования |
| Режим аутентификации | сервисная учётная запись, OAuth-клиент, управляемая идентичность |
| Хранение учётных данных | хранилище секретов, без исходных секретов в документации |
| Ротация учётных данных | ежеквартально или при инциденте |

<a id="3-razresennye-i-zapresennye-operazii"></a>

## 3. Разрешённые и запрещённые операции

| Операция | Разрешена | Условия | Ожидаемые события |
| --- | --- | --- | --- |
| Чтение тикета (`read_ticket`) | Да | Только `project:EXAMPLE`, до 50 записей за запуск | событие запроса вызова инструмента, событие выполненного вызова инструмента |
| Запись комментария к тикету (`execute_ticket_update`) | Да, после согласования | Проверен trusted binding точного snapshot; актуальны grant, ACL и срок | событие требования согласования, запись согласования человеком, событие выполненного вызова инструмента |
| Массовое обновление (`run_bulk_update`) | Только по согласованию двумя лицами | не более 10 записей, отдельная запись согласования | событие требования согласования, запись согласования человеком |
| Удаление записи (`delete_record`) | Нет | Запрещено политикой | событие отказа политики |
| Изменение прав доступа (`modify_access_control`) | Нет | Требует отдельного утверждённого процесса вне агента | событие отказа политики |

<a id="4-limity"></a>

## 4. Лимиты

| Лимит | Значение | Где контролируется |
| --- | --- | --- |
| Максимум вызовов инструментов в минуту | `20` | Политика действий агента / шлюз |
| Максимум записей за рабочий процесс | `50` | Политика коннектора |
| Максимум действий на запись в час | `5` | Политика действий агента |
| Максимум ошибок коннектора за 10 минут | `5` | правило оповещения |
| Максимальная длительность рабочего процесса | 30 минут | лимиты среды выполнения |

<a id="5-priznaki-komprometazii-ili-vyhoda-za-oblast_-dostupa"></a>

## 5. Признаки компрометации или выхода за область доступа

Коннектор должен быть изолирован при любом из признаков:

- резкий рост событий ошибки коннектора;
- вызов операции вне списка разрешённых операций;
- доступ к данным вне утверждённой области;
- действие после истечения срока действия согласования;
- неизвестная сервисная учётная запись;
- изменение прав коннектора без записи изменения;
- подозрение на утечку учётных данных;
- неожиданный внешний эффект после вызова коннектора.

<a id="6-uslovia-izolazii-konnektora"></a>

## 6. Условия изоляции коннектора

| Условие | Немедленное действие | Подтверждение |
| --- | --- | --- |
| Подозрение на компрометацию | Изолировать коннектор, остановить новые вызовы инструментов | [runbook-connector-quarantine.md](./runbook-connector-quarantine.md), событие изоляции коннектора, событие ошибки коннектора |
| Выход за область действия | Сузить область доступа или отключить коннектор | SIEM-запрос; сравнение изменений политики действий агента |
| Раскрытие учётных данных | Изолировать затронутый путь; отозвать/ротировать по установленным scope и полномочиям владельца | Точный credential reference без секрета, зависимые workloads, решение владельца, readback отзыва |
| Несанкционированная запись | Приостановить агента, открыть проверку | событие отказа политики, событие выполненного вызова инструмента, записи согласования |

<a id="8-itogovaa-proverka"></a>

## 8. Итоговая проверка

Перед приёмкой заполните runtime mapping: версия MCP/A2A и transport, OAuth issuer/audience/resource или STDIO credential source, точные backend операции и object ACL. `execute_ticket_update` и `run_bulk_update` — имена из демонстрационной policy; если провайдер использует иные имена, храните явную проверенную таблицу соответствия. Tool discovery не расширяет scope.

Для write/async операций укажите поддержку provider idempotency, job/status lookup, cancel и отдельного readback результата. Проверьте timeout после отправки: outcome остаётся `unknown`, повторная запись не запускается; прекращение local run не отменяет remote job. Для shared credential перечислите все зависимости до ротации и подтвердите, что соседний workload не отключается неявно. Успешный HTTP ответ при revoke/cancel отделяется от фактического результата. Контракт evidence sidecars — [README](./README.md).

| Критерий | Статус |
| --- | --- |
| Коннектор имеет владельца | не начато |
| Тип доступа указан | не начато |
| Область доступа ограничена | не начато |
| Разрешённые и запрещённые операции описаны | не начато |
| Учётные данные хранятся и ротируются по правилам | не начато |
| Условия изоляции описаны | не начато |
| SIEM-запросы и покрытие оповещениями настроены | не начато |
