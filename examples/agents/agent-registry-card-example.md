# Пример карточки агента: дополнение к существующей карточке реестра

Этот шаблон является дополнением для агентного сценария к существующим требованиям реестра AI-систем. Он не заменяет карточку реестра по базовым документам и не вводит отдельный реестр агентов.

Используйте примерные значения. Не указывайте реальные персональные данные, секреты, токены, URL или названия промышленных систем.

---

<a id="kak-ispol_zovat_-sablon"></a>

## Как использовать шаблон

Требование: заполнить этот шаблон только как дополнение к существующей карточке реестра.

Пояснение: реестр из базовых документов остаётся основным источником сведений о системе. Этот шаблон фиксирует только дополнительные поля, нужные для агентного сценария: делегированные полномочия, инструменты и коннекторы, согласование, память, меры контроля среды выполнения и мониторинг.

Подтверждение: ссылка на заполненную карточку реестра по базовым документам, запись процесса подачи, записи согласования, результаты проверки безопасности и подтверждение среды выполнения.

## 1. Идентичность агента

Назначение: однозначно связать агента с существующей карточкой реестра и событиями исполнения.

Обязательные поля:

- идентификатор агента;
- имя агента;
- версия агента;
- идентификатор записи в реестре;
- тип идентичности среды выполнения;
- идентификатор среды выполнения;
- среда.

Пример заполнения:

| Поле | Примерное значение |
| --- | --- |
| Идентификатор агента | `agent-placeholder-001` |
| Имя агента | пример агента с контролируемыми действиями |
| версия агента | `0.1.0` |
| Идентификатор записи в реестре | `registry-record-placeholder` |
| Тип идентичности среды выполнения | сервисная учётная запись |
| Идентификатор среды выполнения | `svc-agent-placeholder` |
| Среда | пилот |

Подтверждение:

- карточка реестра по базовым документам;
- событие исполнения с тем же идентификатором агента;
- ссылка на утверждённую конфигурацию среды выполнения.

<a id="2-biznes-naznacenie"></a>

## 2. Бизнес-назначение

Назначение: зафиксировать рабочую цель агента и границы его использования.

Обязательные поля:

- описание назначения;
- бизнес-процесс;
- разрешённые результаты;
- что не входит в назначение;
- пользователи или бизнес-группа.

Пример заполнения:

- Назначение: агент готовит черновики обновлений для заявок в проекте `EXAMPLE`.
- Бизнес-процесс: первичная сортировка и последующее сопровождение внутренних заявок.
- Разрешённые результаты: чтение заявки, подготовка обновления, запрос согласования.
- Что не входит в назначение: удаление заявок, изменение контроля доступа, внешние уведомления без согласования.

Подтверждение:

- запись процесса подачи;
- бизнес-согласование;
- поле назначения карточки реестра.

- проверяющий по безопасности;

Пример заполнения:

| --- | --- | --- |

| Владелец платформы | `platform-owner-placeholder` | Согласование среды выполнения |

Подтверждение:

- ссылка на RACI;

- подтверждение контакта по инцидентам.

<a id="6-svodka-agentnyh-vozmojnostej"></a>

## 6. Сводка агентных возможностей

Назначение: кратко описать возможности агентного сценария.

Обязательные поля:

- поведение планирования;
- используемые инструменты и коннекторы;
- подготовленные или выполненные действия;
- триггеры;
- использование памяти;
- точки проверки человеком.

Пример заполнения:

- Поведение планирования: агент выбирает порядок чтения заявок и подготовки черновика обновления.
- Инструменты и коннекторы: условный инструмент чтения заявок, условный инструмент записи заявок.
- Действия: чтение заявки, подготовка обновления, запрос согласования, выполнение утверждённого обновления.
- Триггер: только ручной запрос пользователя.
- Память: постоянная память отсутствует.
- Проверка человеком: согласование перед действием на запись.

Подтверждение:

- политика действий агента;
- диаграмма рабочего процесса или список шагов;
- события исполнения из тестового запуска.

<a id="7-delegirovannye-polnomocia"></a>

## 7. Делегированные полномочия

Назначение: зафиксировать, что агент может делать, чего не может делать и где требуется согласование.

Обязательные поля:

- идентификатор полномочий;
- кем выданы полномочия;
- когда выданы полномочия;
- когда истекают полномочия;
- разрешённые действия;
- запрещённые действия;
- действия, требующие согласования;
- условия аварийной остановки.

Пример заполнения:

| Категория | Примерные значения |
| --- | --- |
| Разрешённые действия | чтение заявки, подготовка обновления заявки |
| Действия, требующие согласования | выполнение обновления заявки, отправка внешнего сообщения, массовое обновление |
| Запрещённые действия | удаление записи, изменение контроля доступа, выполнение платежа |
| Условия аварийной остановки | попытка обхода политики, повторяющийся отказ политики, аномалия коннектора |
| Срок действия | `2026-08-13T00:00:00Z` |

Подтверждение:

- [agent-action-policy.yaml](./agent-action-policy.yaml);
- записи согласования;
- события исполнения: событие требования согласования, событие отказа политики, событие срабатывания аварийного отключения.

<a id="8-instrumenty-i-konnektory"></a>

## 8. Инструменты и коннекторы

Назначение: описать разрешённые инструменты и коннекторы и их область действия.

Обязательные поля:

- имя инструмента;
- идентификатор коннектора;
- режим: только чтение, запись или привилегированный доступ;
- разрешённые действия;
- область действия данных;
- модель учётных данных;
- владелец коннектора;
- требование согласования.

Пример заполнения:

| Инструмент/коннектор | Режим | Разрешённые действия | Требуется согласование | Подтверждение |
| --- | --- | --- | --- | --- |
| Условный инструмент чтения заявок | только чтение | чтение заявки, поиск заявки | Нет | Политика действий агента |
| Условный инструмент записи заявок | запись | выполнение обновления заявки | Да | Запись согласования |
| Условный инструмент поиска в справочнике | привилегированное чтение | поиск внутренней группы | Да | согласование владельца коннектора |

Подтверждение:

- согласование коннектора;
- раздел с областями действия инструментов в политике действий агента;
- события исполнения: событие запроса вызова инструмента, событие выполненного вызова инструмента.

<a id="9-klassifikazia-dannyh"></a>

## 9. Классификация данных

Назначение: определить классы данных, с которыми агент может работать.

Обязательные поля:

- разрешённые классы данных;
- запрещённые классы данных;
- порядок обработки исходного чувствительного содержимого;
- подход к ссылкам на входные и выходные данные;
- ссылка на DLP или эквивалентную меру контроля из базовых документов.

Пример заполнения:

- Разрешено: публичные данные, внутренние данные.
- Запрещено: данные ограниченного доступа если отдельная проверка не согласована.
- Исходное чувствительное содержимое в журналах: запрещено.
- Хранение ввода/вывода: только ссылки или хэши.

Подтверждение:

- проверки безопасности;
- события исполнения с классификацией данных;
- примеры журналов без исходного чувствительного содержимого.

<a id="11-model_-soglasovania"></a>

## 11. Модель согласования

Назначение: показать, какие действия требуют согласования и как согласование связывается с событием исполнения.

Обязательные поля:

- тип согласования;
- роли согласующих;
- действия, требующие согласования;
- триггеры двухстороннего согласования;
- срок действия согласования;
- путь отзыва;
- место хранения подтверждения согласования.

Пример заполнения:

| Действие | Тип согласования | Истекает | Подтверждение |
| --- | --- | --- | --- |
| Выполнение обновления заявки | согласование одним лицом | 4 часа | Запись согласования |
| Массовое обновление | согласование двумя лицами | 2 часа | Запись согласования |
| Отправка внешнего сообщения | согласование двумя лицами | 2 часа | Запись согласования |

Подтверждение:

- записи согласования, соответствующие [agent-approval-record.schema.json](./agent-approval-record.schema.json);
- события исполнения с идентификатором согласования;
- идентификатор агента, идентификатор действия, инициатор запроса, область согласования, срок действия и связанные события исполнения в записи согласования;
- для согласования двумя лицами минимум два разных человека по доверенному identity mapping, с актуальными требуемыми ролями; разные значения ID сами по себе этого не доказывают.

<a id="12-limity-ispolnenia"></a>

## 12. Лимиты исполнения

Назначение: ограничить автономность, циклы, повторы и область воздействия.

Обязательные поля:

- максимальная длительность рабочего процесса;
- максимальное число шагов планирования;
- максимальное число повторов;
- максимум действий за рабочий процесс;
- разрешено расписание;
- разрешён автономный цикл;

<a id="16-otkat-i-otklucenie"></a>

## 16. Откат и отключение

<a id="podtverjdenie-ostanovki-i-retirement"></a>

### Подтверждение остановки и retirement

Карточка должна связывать identity агента с schedules, queues, child grants, credentials, remote jobs и memory namespaces. Для каждой внешней операции храните provider job/idempotency reference и результат readback: `pending / cancelled / completed / unknown` в отдельном evidence artifact. Техническая остановка runtime и завершение rollback не доказывают прекращение этих операций. Unknown не превращается в «не выполнено» ради повторного запуска.

При выводе из эксплуатации фиксируют owner, основание, scope, дату и tombstone/epoch без секретов. Доступ к памяти и запуск через restore/replay блокируется по актуальному retirement state. Физическое удаление и backup retention подтверждаются отдельно, после необходимого preservation и установленного решения на cleanup. Новое использование старой identity требует отдельного review; оно не наследует старый approval.

Проверка: late callback, очередь после disable, child на другом credential, restore старого индекса памяти и неизвестный внешний результат. Для каждого теста нужны фактический отказ или provider readback и ссылки на ограниченные evidence. Правила версий схем и семантических связей — [README](./README.md).

Назначение: обеспечить безопасную остановку или откат агентного сценария.

Обязательные поля:

- путь отключения;
- владелец отката;
- целевая версия отката;
- очистка данных и состояния;
- условия повторного включения;
- проверка после отключения.

Пример заполнения:

- Путь отключения: платформенная мера контроля `agent-disable-placeholder`.
- Владелец отката: `rollback-owner-placeholder`.
- Целевая версия: предыдущая согласованная версия.
- Условие повторного включения: проверки безопасности и согласование после анализа первопричины.

Подтверждение:

- тест аварийного отключения;
- инструкция по отключению;
- события исполнения: событие приостановки агента, событие отключения агента, при технической остановке — событие технической остановки агента, событие начала отката, событие завершения отката, событие срабатывания аварийного отключения.

<a id="kriterii-priemki"></a>

## Критерии приёмки

Шаблон считается готовым к проверке, если:

- все обязательные поля заполнены или явно помечены как не применимые с обоснованием;
- есть ссылка на карточку реестра по базовым документам;
- делегированные полномочия описаны для всех действий шире режима только для чтения;
- инструменты и коннекторы и их области действия совпадают с политикой действий агента;
- модель согласования связана с записями согласования;
- поведение памяти описано и связано с шаблоном управления памятью агента;
- события исполнения соответствуют [agent-runtime-events.schema.json](./agent-runtime-events.schema.json);
- согласование промышленной эксплуатации не выдано без проверки безопасности, подтверждения мониторинга, владельца отката и теста аварийного отключения.
