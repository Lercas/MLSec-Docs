# Внутренний аудит ИИ-системы по Приказу ФСТЭК 21

> Опросник для самопроверки ИИ-системы на соответствие требованиям Приказа ФСТЭК 21 (защита ПДн в ИСПДн). Заполняется ИБ-аналитиком совместно с владельцем системы. См. главу [18. Российская специфика](../18-ru-compliance-deep.md).

<a id="0-metadannye-audita"></a>

## 0. Метаданные аудита

Это рабочий опросник, **не исчерпывающий состав мер и не заключение о соответствии**. Разделы «ИИ-специфика», названия продуктов, SLSA, MIG и частоты проверок — варианты инженерной реализации/внутренней политики, а не дословные требования Приказа 21. Применимость, адаптацию базового набора и нормативное основание фиксирует ответственный специалист; УЗ сам по себе не устанавливает универсальную обязанность использовать перечисленный продукт/TEE/HSM/СКЗИ. Периодичность и сроки хранения обосновываются для конкретной системы.

Для каждой применимой строки в комментарии достаточно `{scope/version, owner, evidence_ref, checked_at}`. Ответ «Да» требует факта проверки, «Нет» — плана; `N/A` — причины неприменимости. Если доказательств нет, пишите `не проверено`, не «Да». Матрица применимости и вывод уполномоченного специалиста хранятся отдельно; дублировать их здесь не нужно.

## Общая оценка

<a id="skvoznye-dokazatel_stva-dla-ii-szenaria"></a>

### Сквозные доказательства для ИИ-сценария

| Проверка | Минимальное evidence / отрицательный случай |
|----------|-------------------------------------------|
| Идентичность релиза | Model Card / BOM с model-provider revision, prompt/tool schema/policy и corpus revision; подмена одного артефакта отклоняется |
| Источники и лицензии | Data Card, происхождение/условия весов, данных и API отдельно; неизвестная лицензия не помечена Apache-2.0 по лицензии framework |
| Доступ и HITL | Tenant/principal и action-bound approval; смена получателя/аргумента после подтверждения запрещена backend-ом |
| Факт эффекта | Threat Model hypothesis_id и oracle: outbox/egress/readback; отказ в ответе не скрывает уже выполненный tool-call |
| Приватность и копии | PIA/dataflow охватывает cache/index/telemetry/provider; DP описывает unit/ε/δ/composition либо обоснованно N/A |
| Отзыв и retirement | Отзыв principal/credentials прекращает новые jobs; running/queued jobs, backup/retention exceptions и удаление копий сверены |

Для синтетического `SC-SUPPORT-DRAFT-01` evidence — отчёт sandbox-проверки, где mock-mailbox чужого tenant пуст после атаки с подменой адресата. Он подтверждает только проверенную конфигурацию; перенос результата на production требует отдельной проверки. Изменение provider, прав, tool schema, данных, retention или инцидент повторно открывает затронутые строки. Методика допуска — [14](../14-model-risk-governance.md), checklist агента — [36](../36-ai-agents-production-checklist.md).
