# Уведомления регуляторам

<a id="prinzipy-zapolnenia"></a>

## Принципы заполнения

1. **Фактология > предположения**: описывайте то, что установлено. Гипотезы отмечайте как гипотезы.
2. **Минимизация**: передавайте сведения, необходимые по применимой форме и запросу. Полные базы клиентов и секреты не прикладываются «для убедительности»; защищённые приложения согласуются отдельно.
3. **Timeline из SIEM**: восстанавливайте события по меткам времени из SIEM и audit log LLM Gateway (Rilio).
4. **Норма и факт**: укажите точный акт, пункт и версию; технические TTP — отдельная аналитическая классификация, не основание юридической обязанности.
5. **Параллельное уведомление**: один инцидент может требовать уведомления нескольких регуляторов (например, утечка ПДн в банке = РКН + ФинЦЕРТ).

<a id="marsrut-eskalazii-vnutri-organizazii"></a>

## Маршрут эскалации внутри организации

```
CISO → юридическая служба → Юрист → руководитель организации
         ↓
    Подготовка уведомления (по шаблону)
         ↓
    Согласование уполномоченными лицами / резервный маршрут без переноса законного срока
         ↓
    Отправка по регламентированному каналу (форма РКН / личный кабинет ГосСОПКА / защищённый канал ФинЦЕРТ)
         ↓
    Сохранение отправленного экземпляра, времени, транспортного подтверждения и номера приёма
         ↓
    Поддержка коммуникации с регулятором до закрытия инцидента
```

<a id="kartocka-kontrola-otpravki"></a>

## Карточка контроля отправки

Одна строка — одна обязанность и адресат. Обновление черновика, запись в SIEM и создание тикета не означают отправку.

| Поле | Заполнение |
|------|------------|
| Правовое основание / применимость | {акт, пункт, объект, событие; кто проверил} |
| Исходное событие | {что выявлено / завершено, кем, время с UTC-offset, источник} |
| Законный предел / внутренний target | {два отдельных поля, включая способ расчёта} |
| Подготовка / отправитель / резервный отправитель | {полномочия и контакты} |
| Статус | {черновик / проверяется / готово / отправлено / приём подтверждён / ошибка / требуется уточнение} |
| Свидетельства | {точная версия сообщения, ID, время отправки, квитанция, ответ, защищённое расположение приложений} |

При сбое канала зафиксировать попытку и перейти к заранее проверенному допустимому резервному способу. Сам факт ошибки отправки не останавливает срок. Учебные сообщения хранятся с явной отметкой `УЧЕНИЕ`; они не подаются в рабочую форму регулятора.

## Проверенные основы и границы

- [Банк России: ФинЦЕРТ](https://cbr.ru/information_security/fincert/): организация взаимодействия. Конкретная закрытая схема АСОИ и настройки вашей организации здесь не проверялись.
