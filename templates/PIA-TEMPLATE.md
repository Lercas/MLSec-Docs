До подтверждения условий provider status — `pending`; тесты на вымышленных тикетах не закрывают этот пункт. Для self-hosted без передачи внешнему processor допустимо `N/A: внешний API не используется`, но внутренние копии всё равно описываются.

Применяются ли и почему:

<a id="44-cto-imenno-garantiruet-pet"></a>

### 4.4. Что именно гарантирует PET

| Мера | Обязательное уточнение | Чего из неё не следует |
|------|------------------------|------------------------|
| DP | Единица приватности, adjacency, contribution bound/clipping, механизм, ε/δ, accountant, композиция и публикации | Защита всех runtime-входов, egress, IAM или правомерность обработки |
| Маскирование / псевдонимизация | Какие поля/связи сохранены, где таблица соответствий, тест re-identification | Автоматическая анонимность всей совокупности |
| Federated learning / TEE / encryption | От кого защищаем, где plaintext, кто видит обновления/выход | Автоматическая DP-гарантия или отсутствие model leakage |
| Synthetic data | Происхождение seed, memorization/similarity checks, назначение | Отсутствие ПДн только из-за способа генерации |

Если DP не используется, заполните `DP: N/A, механизм отсутствует`, а не подбирайте ε задним числом. Privacy unit должна соответствовать заявлению: row-level DP нельзя без отдельного обоснования описывать как защиту человека с тысячей строк. Универсального «безопасного ε для K3» здесь нет; параметры, utility и остаточный риск оцениваются совместно. Основание: [NIST SP 800-226](https://csrc.nist.gov/pubs/sp/800/226/final); см. [03](../03-stage1-data-operations.md) и [17](../17-privacy-enhancing-tech.md).

### 8.1. Условия пересмотра и прекращения обработки

Владелец PIA: `{роль}`; evidence status: `{verified/pending/failed}`; дата и ссылка на подтверждающие условия: `{…}`. `N/A` требует причины, `unknown` требует дальнейшего решения. Не назначайте новое лицо для каждой ячейки, если это существующий владелец данных/системы.

Пересмотр обязателен по внутреннему процессу при новой цели, provider/subprocessor/region, retention/training use, новых данных/ACL, инструментах с внешним эффектом и инциденте. При retirement проверьте прекращение новых запросов, отзыв delegated access, удаление attachment/cache/index и запросы processor на удаление; сохранение backup/legal hold опишите отдельно. Отметьте, какие факты подтверждены readback/договором, а какие остаются неизвестными. Retention доказательств не оправдывает бесконтрольное хранение исходных ПДн.
