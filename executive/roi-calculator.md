# ROI Calculator: MLSec Program

> **Версия**: 1.0 · **Дата**: 2026-04-22 · **Формат**: Markdown-описание модели; прежний [roi-calculator.md](roi-calculator.md) не обновлялся и не проверялся в этом пакете.

Документ описывает ROI-модель для программы MLSec. Это сценарная модель для сравнения вариантов, не прогноз гарантированной доходности. Пересмотрено 13.11.2026: риск, измеренная польза и cash flow разделены; формулы ниже не считаются реализованными в существующем XLSX.

<a id="1-zeli-modeli"></a>

## 1. Цели модели

1. Помочь совету директоров принять решение о запуске MLSec program.
2. Оценить break-even point (момент окупаемости).
3. Сравнить сценарии «внедряем сейчас» vs «откладываем на 12 мес» vs «не внедряем».
4. Обеспечить годовой рефреш для quarterly board report.

Ниже проектная структура модели. Состав, ячейки, формулы и цветовые коды существующего `roi-calculator.xlsx` не проверялись; их соответствие этой схеме не заявляется:

7. **Scenarios**: сравнение трёх сценариев.
8. **Sensitivity**: чувствительность к ключевым переменным.

<a id="6-avoided-losses-izbegaemye-poteri"></a>

## 6. Avoided Losses (избегаемые потери)

Сравниваются ожидаемые потери **при текущем процессе** и **при candidate** за один период, а не «без всякой защиты» и идеальная безопасность:

```
EL_baseline(q)  = sum_s(lambda_baseline(s,q)  * mean_loss_baseline(s,q))
EL_candidate(q) = sum_s(lambda_candidate(s,q) * mean_loss_candidate(s,q))
Scenario_avoided_loss(q) = EL_baseline(q) - EL_candidate(q)
```

`lambda` — ожидаемое число событий за квартал, не вероятность «хотя бы одного события». Вероятность и частота не взаимозаменяемы при повторяющихся инцидентах. Значения могут изменяться с workload / tools / scope; автоматическое деление годовой probability на 4 не применяется. Для равномерной exposure допустимо делить годовую **частоту** на 4, явно зафиксировав допущение.

Если сценарии пересекаются (agent action одновременно вызвал leak и downtime), использовать общую incident scenario / event tree либо исключить общие статьи. Не предполагать независимость вероятностей или суммировать один ущерб несколько раз.

Снижение частоты и снижение тяжести оцениваются отдельно. Подписи / gateway / зрелость не задают fixed RiskReduction. Максимальный штраф требует применимого состава и не равен условному mean loss; отсутствие штрафа в пилоте не доказывает его предотвращение. Результат — **сценарная risk-adjusted оценка**, не реализованный cash saving.

<a id="7-acceleration-value-zennost_-uskorenia"></a>

## 7. Acceleration Value (ценность ускорения)

```
Delta_TTP(cohort) = measured_baseline_TTP - measured_candidate_TTP
Cash_benefit(q) = verified_incremental_margin(q) + realised_cash_cost_savings(q)
Capacity_value(q) = separately_valued_productive_time(q)  # не автоматически cash benefit
```

Сравнение фиксирует task mix, revisions, population и период; учитываются ошибки, ручные исправления, принятие результата и эксплуатационные изменения. Сокращение review time не означает высвобождение FTE, пока ресурс не использован / расход не снят. Не считать один эффект одновременно как ускоренную прибыль, часы сотрудников и стоимость задержки.

Эффект попадает в свой период по cohort / adoption, а не автоматически в Q2 после установки gate. Budget candidate сравнивается с baseline на сопоставимых задачах; полная цена успешной принятой задачи включает неуспешные попытки. API success, correctness / policy, operations и customer utility показываются отдельно.

<a id="8-roi-summary"></a>

## 8. ROI Summary

Две перспективы показываются отдельно:

| Показатель | Расчёт / смысл |
|---|---|
| Incremental costs | Candidate minus baseline, по одинаковой perspective и периоду |
| Financial net benefit | Подтверждённые incremental cash benefits − incremental costs; цена capacity отдельно, пока нет cash effect |
| Scenario risk-adjusted net | Financial net benefit + scenario avoided loss; это не cash flow |
| Financial ROI | Financial net benefit / incremental costs, только при положительном ненулевом denominator |
| Scenario ROI | Scenario risk-adjusted net / incremental costs, явно отмеченный сценарий |
| NPV | CF0 + сумма CF(q)/(1+r_q)^q; initial cash flow и конец периода разделены |
| Payback | Когда cumulative financial net становится неотрицательным; может не наступить в горизонте |

Для годовой ставки `r_a` и квартальных потоков `r_q = (1+r_a)^(1/4)-1`. Согласовать nominal/real, валюту, горизонт, налоги и perspective с CFO. Правило [Excel NPV](https://learn.microsoft.com/en-us/office/vba/api/excel.worksheetfunction.npv) о CF0 подтверждено Microsoft: initial flow добавляется отдельно. Workbook этим текстом не проверяется.

**Проверяемый учебный пример**, млн руб / год: baseline частота 0,2 × ущерб 50 = 10; candidate 0,1 × 40 = 4; сценарное уменьшение expected loss = 6. Допустим, incremental cash benefit = 2, incremental program cost = 10. Financial net =−8, financial ROI =−80%; scenario risk-adjusted net =−2, scenario ROI =−20%. Все inputs здесь условные; это проверка арифметики, не эмпирические вероятности / эффект продукта. Если cash benefit неизвестен, financial ROI не вычисляется как подтверждённый результат.

«Первый избежанный штраф» не наблюдается как платёж и не определяет месяц окупаемости. Положительная risk-adjusted оценка может обосновывать решение при отрицательном cash ROI, но эти результаты нельзя подменять друг другом.

<a id="9-scenarios"></a>

## 9. Scenarios

Сравниваются 3 сценария:

1. **Пилот / внедрение сейчас**: относительный Q1 после решения, с текущими контролями и реалистичным adoption.
2. **Отложить на 12 месяцев**: учесть изменения workload, плановые меры и стоимость ожидания с диапазоном.
3. **Продолжить текущий процесс**: existing controls / planned changes / текущие расходы. Отдельно сравнить manual/non-AI и ограничение use case.

Для каждого сценария:
- Ожидаемые потери за 3 года.
- ROI/NPV.
- Диапазоны остаточного риска / эффекта, assumptions и причины предпочтения; неизбежный инцидент не предполагается.

<a id="10-sensitivity-analysis"></a>

## 10. Sensitivity Analysis

Data table (двумерная) показывает чувствительность Year-3 NPV к:
- **Rows**: собственный диапазон частоты PII events (A4), включая нулевой эффект контроля и возможность роста exposure.
- **Columns**: условный ущерб (A5), основанный на сценарии и составе затрат. Отдельно варьировать adoption, review cost и utility вплоть до no-lift / negative lift.

Sensitivity — предложение для реализации; existing XLSX не подтверждён. Показывать области положительного и отрицательного результата, break-even assumptions и зависимые параметры. Цвет не заменяет uncertainty / evidence.

<a id="11-dopusenia-i-ogranicenia-modeli"></a>

## 11. Допущения и ограничения модели

- Модель не учитывает качественные факторы: репутация, доверие регулятора, стратегическая позиция.
- В прежней версии у вероятностей не было проверенного первичного benchmark; они не используются как текущие оценки. Нужны company exposure / expert ranges с источником и ограничениями.
- Три года — учебный горизонт, не универсально адекватный срок; CFO обосновывает его с lifecycle / terminal costs и uncertainty.
- Пример расходов дан в рублях 2026 года. Реальная / номинальная модель и ставка должны быть согласованы; отсутствие инфляции не маскировать номинальной ставкой.
- Не учитываются вложения в инфраструктуру, уже сделанные ранее (sunk cost).

<a id="12-kak-ispol_zovat_"></a>

## 12. Как использовать

1. Согласовать эту методику и input register; прежний XLSX использовать только после отдельной сверки формул и assumptions.
2. На листе **Assumptions**: заменить дефолтные цифры на реальные данные компании (синие ячейки с жёлтой заливкой).
3. Проверить формулы, единицы, периоды, пропущенные inputs, отрицательный эффект, нулевой denominator и отсутствие double counting; автоматический пересчёт existing XLSX не подтверждён.
4. На листе **Sensitivity**: посмотреть границы, в которых программа ещё окупается.
5. Сохранить копию с версией и датой.

Рекомендуется review раз в квартал и при существенном изменении scope. Источники подхода, проверено 13.11.2026: [Green Book 2026](https://www.gov.uk/government/publications/the-green-book--2/the-green-book-2026), [Magenta Book 2026](https://www.gov.uk/government/publications/the-magenta-book/magenta-book-central-government-guidance-on-evaluation-html). Это guidance по appraisal/evaluation, не ставки, штрафы или обязательная финансовая методика РФ.
