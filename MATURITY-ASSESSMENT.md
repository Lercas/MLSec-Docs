# MLSec Maturity Self-Assessment

Опросник для самопроверки зрелости программы ML SecOps и AI Security в организации. Использует темы NIST AI RMF 1.0 (Govern, Map, Measure, Manage), ISO/IEC 42001:2023 и идею уровней зрелости. Это внутренняя инженерная шкала, не официальная модель NIST / ISO / CMMI, сертификация или заключение о безопасности. Тематическая актуализация: 13.11.2026.

<a id="urovni-zrelosti"></a>

## Уровни зрелости

| Уровень | Название | Описание |
|---------|----------|----------|
| 1 | Initial | Процесс не формализован, зависит от героев. Результаты непредсказуемы. |
| 2 | Managed | Процесс описан для отдельных проектов. Делается регулярно, но непоследовательно. |
| 3 | Defined | Процесс описан в корпоративном стандарте, применяется во всех проектах. Есть роли и артефакты. |
| 4 | Quantitative | Процесс измеряется по метрикам. Принимаются решения на основе данных. |
| 5 | Optimizing | Процесс оптимизируется циклически. Улучшения встроены в ежегодный цикл планирования. |

<a id="kak-ozenivat_"></a>

## Как оценивать

Для каждого применимого вопроса выберите подтверждённый уровень 1-5; названия инструментов — примеры, эквивалентный проверенный контроль допустим. Автоматизация не повышает уровень сама по себе. Сначала зафиксируйте scope: системы, tenants, окружения, revisions и дату среза; цели и период улучшения определите по риску и ресурсам.

К оценке приложите `owner → evidence_ref → revision → дата проверки → следующий пересмотр`. Evidence включает конфигурацию, результат теста и наблюдаемый эффект; при запрете проверяйте также разрешённый сценарий. Нет доступного oracle / readback — `unknown`, а не уровень 1 или успешная проверка. Неприменимость — `N/A + причина + owner`, не балл 1.

## Подсчёт и интерпретация

Среднее по домену вычисляйте только по подтверждённым применимым баллам; вместе с ним публикуйте `оценено / применимо`, количество `unknown` и `N/A`. Если нет подтверждённых вопросов — балл домена `unknown`. Общий индекс — среднее доступных доменных баллов с явным числом оценённых доменов / 10; неполный индекс маркируйте предварительным. Не сравнивайте периоды без сверки scope, исключений и методики.

Критические пробелы (например, подтверждённый cross-tenant доступ, неработающий отзыв или uncontrolled egress) указывайте отдельно с owner и сроком. Они не исчезают в среднем балле; решение о выпуске / эксплуатации принимается по отдельным gates и принятым рискам. `N/A` и `unknown` не повышают полноту проверки.

| Общий балл | Интерпретация |
|------------|---------------|
| 1.0 - 1.9 | В оценённых доменах мало устойчивых процессов. Приоритет: реестр систем, разрешённые маршруты, IR и критические разрывы. |
| 2.0 - 2.9 | Есть отдельные элементы, но нет системы. Фокус: стандартизация, роли, политики. |
| 3.0 - 3.9 | В оценённых доменах процессы описаны и регулярно выполняются; проверить неоценённые системы, исключения и critical gaps. |
| 4.0 - 4.9 | В оценённых доменах процессы измеряются; сохранять проверки актуальности evidence, границ scope и остаточных рисков. |
| 5.0 | Высокий подтверждённый уровень процесса в оценённом scope; это не отсутствие уязвимостей или сравнительный рейтинг индустрии. |

<a id="periodicnost_"></a>

## Периодичность

- Самооценка: каждые 6 месяцев.
- Внешняя верификация (внутренний аудит, внешний ассессмент): ежегодно.
- Целевые улучшения: по существенности разрывов, owner и сроку; рост балла не подменяет устранение запрещённого эффекта.
