# IR-05. Shadow AI Data Leak

> Severity: SEV2 по умолчанию. SEV1 если утекли ПДн (K2+), коммерческая тайна, данные клиентов, исходный код Tier 1 систем, или обнаружена массовость использования.
>
> SLA containment: 1 час. SLA полного закрытия: 10 рабочих дней.

<a id="1-opredelenie-i-priznaki"></a>

## 1. Определение и признаки

Shadow AI: использование сотрудниками неконтролируемых LLM-сервисов (ChatGPT, Claude, DeepSeek, Gemini, корпоративно-несанкционированные ассистенты, локальные developer tools, чат-боты на личных устройствах) для рабочих задач в обход корпоративных систем, ведущее к утечке данных.

Типовые инциденты: (а) разработчик скопировал кусок кода с секретами / IP компании в ChatGPT, (б) менеджер попросил LLM суммаризовать конфиденциальный документ, (в) отдел поддержки использует внешний LLM для работы с тикетами клиентов (с ПДн), (г) на рабочем ноутбуке установлен VSCode с Copilot / Cursor без корпоративных guardrails, (д) сотрудник загрузил базу клиентов в excel-copilot на личном OpenAI-ключе.

<a id="11-triggery-obnarujenia-ioc"></a>

### 1.1. Триггеры обнаружения (IoC)

- DLP / CASB алерт об исходящем запросе на `*.openai.com`, `*.anthropic.com`, `*.deepseek.com`, `*.gemini.*`, `*.perplexity.ai`, `*.groq.com`, `*.mistral.ai` и иные LLM-домены от корпоративных устройств.
- Network flow: HTTPS к LLM-доменам из VPN / офиса, не проходящий через корпоративный LLM gateway.
- Endpoint DLP (браузерное расширение): копирование большого блока текста в известный LLM-чат.
- Proxy log: access к LLM-вебам с большим объёмом POST в `api/chat/completions` / `messages`.
- Обнаружение API-ключей OpenAI / Anthropic / прочих LLM-провайдеров в корпоративных репозиториях (git-leaks).
- Запись в expense system оплаты OpenAI / Anthropic / прочих LLM-провайдеров на сотрудника.
- Результаты периодического аудита SaaS-инструментов (Microsoft Purview, Netskope, Zscaler).
- Публикация утёкших данных (Pastebin, HaveIBeenPwned, darkweb) или упоминание корпоративного домена в инцидентах у вендоров.
- Жалоба клиента / партнёра о том, что LLM выдаёт данные, похожие на их.

<a id="12-istocniki-dannyh"></a>

### 1.2. Источники данных

- CASB (Microsoft Purview, Netskope, Zscaler).
- Proxy / egress firewall logs (Squid, Palo Alto, Fortinet, Check Point).
- EDR / endpoint DLP (Crowdstrike, SentinelOne, корпоративный агент).
- DNS logs (запросы к LLM-доменам).
- Secret scanner (git-leaks, truffleHog) - для обнаружения API-ключей.
- Browser extension logs (если развёрнуто расширение контроля).
- Expense / procurement system.
- SSO / IdP logs (сторонние LLM-сервисы через OAuth).
- HR / onboarding records (кто, какой функционал выполняет).

<a id="2-podgotovka-preparation"></a>

## 2. Подготовка (Preparation)

- [ ] Утверждена и коммуницирована AI Use Policy с чёткой матрицей «какие данные можно использовать в каких сервисах».
- [ ] Запущен корпоративный LLM gateway / sanctioned alternative (собственный прокси к OpenAI / Anthropic, либо self-hosted решение) как «sanctioned path».
- [ ] CASB / egress DLP настроен на детекцию и блокировку неконтролируемых LLM-сервисов.
- [ ] Secret scanner встроен в pre-commit / pre-push и CI.
- [ ] Endpoint DLP / Browser extension контролирует copy-paste в известные LLM-сайты.
- [ ] Обучение (security awareness) проведено и задокументировано, повторяется раз в 6-12 месяцев.
- [ ] Есть easy-of-use sanctioned path (сотрудник может легко обратиться за помощью через корпоративный LLM): это главный фактор снижения shadow AI.
- [ ] SIEM-правила: `shadow-01-external-llm`, `shadow-02-saas-ai-tool`, `shadow-03-api-key-in-repo`.
- [ ] Юр. служба и HR согласовали процедуру реагирования на нарушение (дисциплинарные меры vs образовательные).

<a id="3-detection-amp-analysis"></a>

## 3. Detection & Analysis

<a id="31-triaj-l1-0-15-minut"></a>

### 3.1. Триаж (L1, 0-15 минут)

1. Подтвердить alert: источник (CASB / DLP / secret scanner / жалоба), тип события, сотрудник, устройство, точное время.
2. Определить затронутый сервис: какой именно LLM (ChatGPT Free / Team / Enterprise, Claude, DeepSeek, другое).
3. Оценить предварительный объём: один эпизод или серия; один сотрудник или отдел.
4. Открыть инцидент `ML-SHADOW-AI`, SEV2 по умолчанию.

<a id="32-analiz-l2-mlsec-analyst-sovmestno-s-hr-ur-slujboj-15-60-minut"></a>

### 3.2. Анализ (L2 MLSec Analyst совместно с HR / юр. службой, 15-60 минут)

1. **Что утекло**:
   - Текст: из какого источника (документ, код, база данных, тикет клиента).
   - Объём: количество символов / строк / записей.
   - Классификация: K0-K4, ПДн, КТ, клиентские данные, секреты.
   - Наличие уникальных идентификаторов (имена, INN, email, номера договоров, ключи).
2. **Куда утекло**:
   - Сервис: бесплатный / платный, корпоративный / личный аккаунт.
   - Условия сервиса: обучается ли модель на данных (ChatGPT Free vs Team/Enterprise: разные политики).
   - Retention: сколько хранятся данные у провайдера.
   - Локация серверов (для 152-ФЗ / 242-ФЗ).
3. **Кто**:
   - Сотрудник, роль, отдел, давность в компании.
   - Намеренно или по незнанию (прошёл ли тренинг, есть ли ознакомление с AI Use Policy).
   - Уникальный случай или повторяющееся поведение.
4. **Почему**:
   - Отсутствует sanctioned alternative?
   - Sanctioned alternative неудобен / ограничен по функциям?
   - Сотрудник не знал о политике?
   - Давление дедлайнов / производительности?
5. **Масштаб в организации**:
   - Сколько ещё сотрудников используют shadow AI (query CASB за 30 / 90 дней).
   - Какие отделы чаще всего.
   - Какие сервисы наиболее популярны.

<a id="33-klassifikazia"></a>

### 3.3. Классификация

| Признак | SEV1 | SEV2 | SEV3 |
|---|---|---|---|
| Утёкшие данные | ПДн K2+, КТ, данные клиентов, исходники Tier 1 | Внутренние документы K1, не-критичный код | Публичные материалы, уже открытые данные |
| Намеренность | Намеренный обход, саботаж | Небрежность | Случайность (копировал draft) |
| Объём | > 10^4 записей или ядро IP | Единичные эпизоды | Единичный эпизод без significant impact |
| Регулярность | Систематическое поведение отдела | Повторяющийся индивидуальный случай | Единичный инцидент |

<a id="4-containment"></a>

## 4. Containment

<a id="41-nemedlennye-dejstvia-0-15-minut-ot-podtverjdenia-sev2"></a>

### 4.1. Немедленные действия (0-15 минут от подтверждения SEV2+)

1. **Блокировка на egress**: занести конкретный сервис в CASB block-list, включить geo-fencing / DNS block.
2. **Блокировка аккаунта пользователя в LLM-сервисе** (если применимо через SSO): revoke OAuth token, disable SSO-linked account.
3. **Отзыв корпоративных учётных данных** у сотрудника, если в LLM попали пароли / секреты (ротация SSO, VPN, SSH, cloud credentials).
4. **Для ключей в репозиториях**: немедленно отозвать затронутые ключи у issuer и проверить отказ доступа. Переписывание git history — отдельная согласованная операция после сохранения evidence; оно не отзывает ключ и не удаляет чужие clones / caches.
5. **Уведомить**: CISO, HR, юр. служба, DPO (для ПДн), руководитель сотрудника.

<a id="42-takticeskie-dejstvia-15-min-4-casa"></a>

### 4.2. Тактические действия (15 мин - 4 часа)

1. **Провайдер**: уполномоченный владелец аккаунта / юрист направляет scoped запрос о сохранении необходимых evidence, ограничении доступа и удалении, где доступно. Проверить конкретный продукт, аккаунт, договор и категории данных; запрос не доказывает исполненное удаление из backups, logs или обученной модели.
2. **Контактирование затронутых лиц** (при ПДн): юрист / DPO определяет применимое право и условия уведомления. Порог высокого риска из GDPR ст. 34 не переносится автоматически в 152-ФЗ.
3. **Публичные упоминания**: мониторинг упоминаний данных вовне (Have I Been Pwned, pastebin, darkweb, корпоративный threat intel).
4. **Документ / код исходник**: пересмотр классификации, перенос в защищённое хранилище.
5. **Коммуникация команде**: внутренняя рассылка о инциденте (без имён), напоминание политики.
6. Для финсектора / КИИ: проверить применимые основания и сроки уведомления ФинЦЕРТ / ГосСОПКА по [главе 18](../18-ru-compliance-deep.md).
7. Для ПДн: уведомление РКН об утечке согласно 152-ФЗ ст. 21 ч. 3.1 (первичное в течение 24 часов, детальное по результатам внутреннего расследования — в течение 72 часов), с шаблоном из [templates/regulator-notifications/](../templates/regulator-notifications/).

<a id="5-eradication-amp-recovery"></a>

## 5. Eradication & Recovery

<a id="51-eradication-dni-1-5"></a>

### 5.1. Eradication (дни 1-5)

1. **Root cause**:
   - Sanctioned alternative отсутствует / недостаточен?
   - Пользователь не знал о политике?
   - Технический gap (обход CASB)?
2. **Устранение корневой причины**:
   - Развернуть / расширить sanctioned LLM gateway.
   - Включить дополнительные функции в корпоративном ассистенте (доступ к документам, кодовым БД).
   - Расширить CASB / DLP: добавить больше LLM-доменов, улучшить категоризацию.
   - Расширить endpoint DLP на прочие каналы (IM, webmail).
   - Обновить обучение security awareness на основе реального кейса.
3. **Дисциплинарные / образовательные меры** (по HR / юр. службе):
   - Первое нарушение: напоминание, обучение, protokol.
   - Повторное / умышленное: разбирательство HR, дисциплинарное взыскание, вплоть до увольнения.
   - Для умышленного разглашения КТ: оценка перспективы по ст. 183 УК РФ.

<a id="52-recovery-dni-3-10"></a>

### 5.2. Recovery (дни 3-10)

1. Подтвердить, что sanctioned alternative работает и пользователям о нём известно.
2. Коммуникация (внутренний блог / Slack / all-hands): AI Use Policy, почему shadow AI рискован, каков sanctioned path.
3. Обновление AI Use Policy и переподписание (если значимые изменения).
4. Аудит CASB / DLP: улучшить покрытие, снизить ложные срабатывания.
5. Обновить onboarding процесс: раннее ознакомление с AI Use Policy, раннее предоставление sanctioned tools.

---

<a id="53-zakrytie-kanala-i-podtverjdenie-ostatocnogo-riska"></a>

### 5.3. Закрытие канала и подтверждение остаточного риска

Домен в proxy log — индикатор обращения, а не доказательство состава утёкшего текста. Не делайте вывод об обучении на данных по одному названию сервиса или типу оплаты: зафиксируйте продукт, настройки на момент события, опубликованные условия и доступные provider records.

| Что проверяем | Owner / evidence | Что не считается завершением |
|---|---|---|
| Корпоративная интеграция / OAuth | IAM owner: отзыв grant, refresh и sessions, безопасный deny-test старого пути | Только disable SSO при живой сессии у сервиса |
| Scheduled agent / plugin с личным ключом | Endpoint / integration owner: остановка расписания, inventory background jobs, readback issuer | Только закрытая вкладка браузера |
| Загруженный файл / shared link | Account owner + юрист: ID объекта, доступ получателей, ответ провайдера и ограничения удаления | Удалённый локальный файл или неподтверждённый запрос support |
| Раскрытый корпоративный секрет | Владелец системы: отзыв у issuer, отсутствие нового использования, список зависимостей | Удаление секрета из чата без ротации |
| Разрешённая замена | Product owner: аналогичная рабочая задача доступна через одобренный канал с допустимыми данными | Автоматическое копирование истории из личного сервиса в корпоративный |

В incident report отдельно записать: подтверждённо раскрытое, предполагаемое, неизвестное, остаточный риск и owner дальнейших действий. Обучение проверяется практическим выполнением задачи и сообщением о сомнительном канале, а не только отметкой о прохождении курса — см. [главу 21](../21-people-process.md). Применяются [общие условия IR](README.md), тематическая сверка **13.11.2026**.

<a id="6-post-incident-activity"></a>

## 6. Post-Incident Activity

<a id="61-obazatel_nye-artefakty-v-tecenie-15-rabocih-dnej"></a>

### 6.1. Обязательные артефакты (в течение 15 рабочих дней)

- [ ] Incident report (redacted) с timeline, объёмом утечки, корневой причиной, мерами.
- [ ] Обновлённая AI Use Policy (при необходимости).
- [ ] Обновлённые конфигурации CASB / DLP.
- [ ] Обновлённая программа обучения.
- [ ] Уведомления регуляторов и субъектов ПДн (если применимо).
- [ ] HR-протокол / решение по сотруднику.
- [ ] Lessons Learned встреча: HR + ИБ + ML-команда + юр. служба.
- [ ] Анти-рецидивная проверка через 30 дней: повторный аудит поведения отдела.

<a id="62-metriki"></a>

### 6.2. Метрики

- Detection lag: от эпизода до обнаружения.
- Shadow AI incidents rate: кол-во эпизодов / месяц / 1000 сотрудников (должно падать со временем).
- Sanctioned LLM adoption rate: % сотрудников, использующих корпоративный путь.
- Training completion rate: % ознакомленных с AI Use Policy.
- Time to notify: отдельно первичное и дополнительное сообщения РКН при применимости; 24 / 72 ч не являются универсальным сроком уведомления субъектов ПДн. Основания и точку отсчёта подтверждает юрист.

```
CASB / DLP / Secret scanner (обнаружение)
    ↓ [любая SEV]

    ↓ [ПДн / КТ / массовость]
CISO + DPO + руководитель отдела
    ↓ [значимая утечка]
AI Risk Committee + CEO
    ↓ [обязательное]
РКН (24 ч по 152-ФЗ) / ФинЦЕРТ / ГосСОПКА / клиенты (при ПДн)
```
