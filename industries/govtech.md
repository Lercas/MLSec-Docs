# GovTech: MLSec playbook

> **Версия**: 1.1 · **Дата**: 2026-05-29
> **Регуляторы**: ФСТЭК, ФСБ, Минцифры, Роскомнадзор, ГосСОПКА, НКЦКИ
> **Нормативный контекст**: Указ Президента РФ № 250, 187-ФЗ (КИИ), 149-ФЗ, 152-ФЗ, применимые требования ФСТЭК / ФСБ к конкретной системе, 258-ФЗ (ЭПР). Перечень не заменяет проверку редакций, переходных условий и применимости по главе 18.

<a id="1-kontekst"></a>

## 1. Контекст

Для ГИС, ЕПГУ, МФЦ и ведомственных платформ определяется статус конкретной системы, состав информации, угрозы, применимые требования защиты и закупок. Это не означает автоматической сертификации каждой модели как СЗИ, принадлежности каждого сервиса к КИИ или одинаковой криптографии для каждого соединения. AI-компонент включается в проект защиты и контроля изменений; актуальная юридическая матрица — в [главе 18](../18-ru-compliance-deep.md).

<a id="2-prioritetnye-use-cases"></a>

## 2. Приоритетные use cases

| Use case | Tier | Риск |
|---|---|---|
| Автоматизированное принятие решений о гос. услугах | 1 | Нарушение прав граждан, административная ответственность |
| Чат-бот ЕПГУ / МФЦ | 2 | Дезинформация, утечка PII граждан |
| Voice assistant call-центра | 2 | Deepfake обход |
| RAG по законодательству для сотрудников | 2-3 | Утечка закрытой методологии |
| Анализ документооборота | 3 | Компрометация целостности документов |
| Distribution of social benefits | 1 | Bias на социальные группы |
| Code-ассистенты для разработчиков ГИС | 2-3 | Supply chain в критических системах |

<a id="3-regulatornye-tocki"></a>

## 3. Регуляторные точки

<a id="ukaz-250-nkzki"></a>

### Указ 250 (НКЦКИ)

Указ Президента РФ № 250 от 01.05.2022 (с изменениями):
- Запрет использования иностранных ИБ-средств в критических системах.
- Создание структурных подразделений по ИБ в ведомствах.
- Полномочия ФСБ на инспекцию.

**MLSec-последствия**:
- Отделять требования к средствам защиты информации от требований к прикладной модели / закупке / обработке данных. Указ 250 не следует пересказывать как универсальное правило «любая LLM только отечественная».
- Для модели, code-assistant, telemetry и внешнего grader отдельно подтвердить разрешённое размещение, обработку и получателей. Self-hosted open-source сам по себе не доказывает compliance и не разрешает любой импорт модели.

<a id="187-fz-kii"></a>

### 187-ФЗ (КИИ)

Статус ГИС не устанавливает статус объекта КИИ. При применимости 187-ФЗ отдельно определяются субъект, объект и результаты категорирования; требования к значимому объекту не переносятся на любую ведомственную RAG-систему.

**MLSec-аспекты**:
- AI-компоненты объекта КИИ подпадают под контроль ФСТЭК/ФСБ.
- Управляемое отключение AI — предлагаемый технический контроль; конкретное требование и безопасный режим определяются проектом системы.
- Регулярные проверки ФСТЭК (Приказ 239).
- Участие в ГосСОПКА (см. ниже).

<a id="fstek-prikazy"></a>

### ФСТЭК Приказы

**Приказ 117** (ГИС): требования защиты информации проверяются по действующей редакции и переходным условиям. Не приписывайте исходной редакции универсальные AI-обязанности без чтения конкретного пункта и вступивших в силу поправок; reference для проверки — [официальное опубликование](https://publication.pravo.gov.ru/document/0001202506170011).
**Приказ 21** (ПДн): требования к защите персональных данных (параллельно 152-ФЗ).
**Приказ 31** (АСУ ТП): требования для АСУ ТП (применимо к промышленным ГИС).
**Приказ 239** (значимые объекты КИИ): дополнительные требования.

Применимость 117, 21, 31 и 239 устанавливается для объекта и обработки; механическая формула «все приказы одновременно для любого AI» не заменяет проект защиты.

<a id="gossopka"></a>

### ГосСОПКА

Государственная система обнаружения, предупреждения и ликвидации последствий компьютерных атак. ГосСОПКА собирает incident-репорты и IoC.

**Требования к AI-инцидентам**:
- Основание и срок сообщения определяются действующим порядком и статусом ресурса / объекта, а не словом «критичный» в alert. Матрица приказа ФСБ № 547 — в [главе 18](../18-ru-compliance-deep.md).
- Установленные адресатом форма, канал и состав сообщения с сохранением evidence отправки.
- Участие в обмене IoC.

<a id="149-fz-proekt-popravok-o-markirovke-ai-kontenta"></a>

### 149-ФЗ (проект поправок о маркировке AI-контента)

Статус конкретного проекта поправок, принятого акта и дату вступления проверяют отдельно: ожидаемая дата из новости не является действующей обязанностью. При публикации AI-generated материалов владелец сервиса документирует происхождение и применимые правила информирования; актуальная сверка — [глава 29](../29-watermarking-attribution.md).

<a id="epr-v-sfere-ii-258-fz-moskovskij-eksperiment-123-fz"></a>

### ЭПР в сфере ИИ (258-ФЗ; московский эксперимент 123-ФЗ)

Рамочный механизм экспериментальных правовых режимов в сфере цифровых инноваций — **258-ФЗ от 31.07.2020**. Московский эксперимент по специальному регулированию ИИ — **123-ФЗ от 24.04.2020** (введён с 01.07.2020 на 5 лет; базовое окно истекло ~01.07.2025 — проверить факт продления).
- Уведомление Минцифры.
- Отдельный режим compliance.
- Применимо к исследовательским ГИС-проектам.

<a id="4-minimal_nyj-nabor-kontrolej"></a>

## 4. Минимальный набор контролей

<a id="data"></a>

### Data
- [ ] Классификация по 149-ФЗ/152-ФЗ/187-ФЗ: точная карта данных.
- [ ] Датасеты хранятся на сертифицированных СЗИ (ФСТЭК).
- [ ] Локализация и трансграничная передача оценены как отдельные вопросы; нет автоматического разрешения / запрета cloud по одному названию закона.
- [ ] Размещение, внешние APIs, telemetry и subprocessors допущены для конкретных данных.

<a id="models"></a>

### Models
- [ ] Модель / runtime соответствуют установленным для сценария ограничениям закупки, происхождения, обработки и защиты.
- [ ] Сертификация моделей, если они являются частью СЗИ.
- [ ] Подпись ГОСТ-крипто (отечественные удостоверяющие центры).
- [ ] Model Card на русском.

<a id="infrastructure"></a>

### Infrastructure
- [ ] Отечественные ОС (Astra Linux, РЕД ОС, Alt Linux).
- [ ] Отечественные СУБД (Postgres Pro, Тантор).
- [ ] Криптографическая защита и её реализация определены для конкретных потоков / оснований, без автоматического требования одинакового ГОСТ-TLS ко всему AI-стеку.
- [ ] Сертифицированные средства защиты (SCAN-V, VipNet, КриптоПро).

<a id="access"></a>

### Access
- [ ] ЕСИА для пользователей-граждан.
- [ ] Внутренний SSO с MFA для сотрудников.
- [ ] ГосУслуги Бизнес для B2G.
- [ ] Vault (или российский аналог) для секретов.

<a id="monitoring"></a>

### Monitoring
- [ ] Интеграция с ГосСОПКА.
- [ ] КУМА / MaxPatrol SIEM / любой сертифицированный SIEM.
- [ ] SIEM rules в [siem/kuma/](../siem/kuma/) готовы к импорту.
- [ ] Состав и retention логов обоснованы применимыми требованиями, расследованием и минимизацией данных; нет универсальных трёх лет для всех traces.

<a id="ai-specific"></a>

### AI-specific
- [ ] Kill-switch обязателен.
- [ ] Human-in-the-loop для всех Tier 1 автоматизированных решений.
- [ ] Explanation capability (152-ФЗ + future 149-ФЗ).
- [ ] Bias audit для решений, касающихся граждан.

<a id="ir"></a>

### IR
- [ ] Playbook утверждён владельцем системы; внешнее согласование проводится там, где оно предусмотрено применимым порядком.
- [ ] Notification matrix содержит применимые основания, сроки, адресатов и точку отсчёта.
- [ ] Tabletop с участием НКЦКИ раз в полгода.
- [ ] Forensics tools сертифицированы.

<a id="5-otdel_nye-pravila-dla-avtomatizirovannyh-resenij-o-grajdanah"></a>

## 5. Отдельные правила для автоматизированных решений о гражданах

Статья 16 152-ФЗ ограничивает решения, основанные **исключительно** на автоматизированной обработке ПДн, порождающие юридические последствия или иным образом затрагивающие права и законные интересы. Допустимость определяется письменным согласием или предусмотренным федеральным законом случаем с гарантиями прав; обычная кнопка «оспорить» не создаёт такого основания. Порядок разъяснений и возражений проверяется с юристом — см. [официальный текст 152-ФЗ](https://mintrud.gov.ru/docs/laws/130).

Обоснование, review и журналы сохраняются по применимому назначению / сроку; универсальные пять лет для каждого AI-решения этим разделом не устанавливаются.

**Техническое**:
- Self-service UI с explanations (см. [главу 30](../30-interpretability-for-security.md)).
- Audit лог решений.
- Workflow для обжалования.

<a id="pilot-spravka-o-poradke-polucenia-uslugi"></a>

### Пилот: справка о порядке получения услуги

**Сценарий**: RAG отвечает на вопрос по опубликованным регламентам в изолированном прототипе. Только синтетическое обращение; нет реестра граждан, автоматического назначения выплаты, отказа в услуге или отправки официального решения. Владелец услуги утверждает корпус, редакции и допустимое назначение; юрист — правовую корректность ответа, ИБ — границы доступа.

| Проверка | Требуемое поведение | Evidence |
|---|---|---|
| Два регламента с разными датами действия | Ответ указывает применимую редакцию / дату; конфликт не скрывается | Content owner: retrieved revision и ссылка на первичный текст |
| В обращении просьба «изменить статус заявления» | Внешнего изменения нет; разрешён только справочный ответ | Service owner: test registry readback |
| Инструкция из вложения подменяет условия выплаты | Недоверенный документ не становится источником официального требования | QA / юрист: разметка утверждение → источник |
| Вопрос требует ведомственных / персональных сведений | Отказ по scope без чтения закрытого индекса; разрешённая публичная справка работает | IAM owner: deny / allow audit |

В пилоте сравниваются корректность основания, редакции и полнота маршрута обращения; затем отдельно время подготовки **проверенной** справки сотрудником. Доля самостоятельных ответов / уменьшение времени не разрешает принимать юридически значимые решения автоматически. Ошибочная ссылка на недействующую норму — stop condition для затронутой темы до исправления корпуса.

Тематическая сверка **13.11.2026**: [первичный текст 152-ФЗ](https://mintrud.gov.ru/docs/laws/130). Содержание новых AI-поправок к требованиям ГИС здесь не квалифицируется без подтверждения действующей редакции; нормативное применение согласуется с [главой 18](../18-ru-compliance-deep.md).
